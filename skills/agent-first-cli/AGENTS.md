# AGENTS.md — agent-first-cli

This is the skill's enforcement contract. It states one rule and how to read it in both directions. Mechanics live in `references/validate.md` and `references/verify.md`; the axis list lives in `references/eval.md`.

## Self-Initialization Contract

This skill is self-initializing. On first load in a project, the skill instructs the reading agent to write a small set of re-invocation cues into the host project so subsequent calls route correctly without re-running setup:

- **Non-GSD harnesses:** cues are written into `AGENTS.md` at the project root inside a `<!-- agent-first-cli begin --> ... <!-- agent-first-cli end -->` marker block. `AGENTS.md` is created if it does not exist.
- **GSD harnesses** (`.gsd/PREFERENCES.md` or `~/.gsd/PREFERENCES.md` present): cues go into `.gsd/PREFERENCES.md` inside the same marker block. `AGENTS.md` is **not** written in this case and stays untouched.

Re-runs without `--force` are idempotent: an existing marker block causes setup to skip silently. `agent-first-cli setup --force` replaces the existing marker block in place. The canonical cue wording and procedure live in `references/setup.md`; that file is the source of truth — this section only documents the contract.

## Strict Bidirectional Coverage Rule

Every axis of the agent-first rubric in `references/eval.md` must map to an Active R### in the project's `REQUIREMENTS.md` OR be marked `out-of-scope` with a reason. Every R### generated by this skill (via `references/requirements.md`) must map to at least one axis OR carry an explicit justification in its Notes field. An uncovered axis or an orphan R### **is an error**, not a warning. Run `agent-first-cli validate` (plan-mode) or `agent-first-cli verify` (impl-mode) to surface errors.

## Axis → R### (top-down)

Read coverage from the rubric downward. For each axis in `references/eval.md`, find the R### in `REQUIREMENTS.md` that satisfies it, or confirm it is explicitly marked `out-of-scope` with a reason. If neither, the project has an uncovered axis: stop and reconcile before execution.

| Axis state | Required entry in REQUIREMENTS.md |
|---|---|
| Covered | One or more Active R### with `Axis: N` in Notes |
| Out of scope | An R### (or a Notes entry on a covering R###) saying `out-of-scope: {reason}` |

## R### → Axis (bottom-up)

Read coverage from requirements upward. Every R### that this skill suggests must carry an `Axis: N` tag (matching a rubric axis) in its Notes field, OR an explicit justification if it intentionally does not map to a rubric axis. An R### with no axis tag and no justification is an orphan R### and is an error.

| R### shape | Verdict |
|---|---|
| Notes includes `Axis: N` | Covered |
| Notes includes a justification | Allowed exception |
| Neither | Orphan R### — error |
