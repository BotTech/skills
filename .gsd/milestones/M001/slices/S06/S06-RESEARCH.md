## Critical Findings

### 1. Distribution model: BotTech skills are directory-auto-discovered, not lock-tracked
- `npx skills list` shows BotTech's own skills (`gsd-new-cli-project`, `timesheet` as of last upstream sync) under "Project Skills" pointing at `~/src/bottech/skills/skills/<name>`.
- `skills-lock.json` is reserved for third-party skills added via `npx skills add <github>`. It is not committed to the BotTech repo and is gitignored in the upstream clone.
- **Implication for S06:** there is no `skills-lock.json` to edit. R015's "audit skills-lock.json" resolves to a non-action; the migration concern reduces to: "existing users who installed `gsd-new-cli-project` will see it disappear and `agent-first-cli` appear on next `npx skills` sync."

### 2. Existing user installs (the real R015 problem)
Currently installed via `npx skills add https://github.com/bottech/skills` before this milestone:
- `~/.agents/skills/gsd-new-cli-project/` — real directory with SKILL.md (10.6 KB).
- `~/.claude/skills/gsd-new-cli-project` — symlink to the above.
- `~/.agents/skills/agent-dx-cli-scale/` — real directory. (Note: this is a **different skill**, distributed separately by another author; **do not confuse with `agent-dx-cli-eval`** which was only ever a BotTech repo directory, never installed via the skills CLI.)
- The README's `agent-dx-cli-eval` entry was an in-repo reference, not an installable skill.

**Migration impact after merge:**
- Fresh installs of BotTech skills via `npx skills add` will install `agent-first-cli` and `timesheet`. They will not install `gsd-new-cli-project` (directory gone) or `agent-dx-cli-eval` (directory gone).
- Existing installs of `gsd-new-cli-project` will become stale on the user's disk until they re-run `npx skills add` or `npx skills remove gsd-new-cli-project`. No automatic symlink breakage — the file just stays put as an orphan.
- The old `agent-dx-cli-eval` skill was never installable via `npx skills`, so no install-side migration is needed for it.

**R015 mitigation choice:** write a clear migration note in the README explaining that `gsd-new-cli-project` users should switch to `agent-first-cli`. A symlink fallback (`skills/gsd-new-cli-project` → `skills/agent-first-cli`) is **not** recommended because it pollutes the install with two copies of every reference load and confuses the auto-discovery. Plain migration note wins.

### 3. Submodule init: required, not auto-handled
- `git clone https://github.com/bottech/skills` → `skills/agent-first-cli/assets/samples/gitignorer/` is empty (just the gitlink).
- `git clone --recurse-submodules https://github.com/bottech/skills` → submodule populated.
- **`npx skills add` does NOT run `git submodule update --init`.** The `skills` CLI copies/symlinks the directory tree; it does not interpret `.gitmodules`. Verified by examining `npx skills --help`: no submodule option, no init step.
- **Implication:** for `npx skills add` users, the submodule path will be empty after install. Two options:
  - (a) Document the manual `cd ~/.agents/skills/agent-first-cli && git submodule update --init --recursive assets/samples/gitignorer` step in README (clunky — user has to know the install path).
  - (b) Document that `assets/samples/gitignorer/` requires manual setup, and provide a one-liner that works whether the skill was added via `npx skills` or via `git clone`.
- Option (b) is simpler and works for both install paths. Concretely:
  ```
  # After installing or cloning, populate the sample asset:
  git clone --depth 1 https://github.com/BotTech/gitignore.git skills/agent-first-cli/assets/samples/gitignorer
  ```
- Or, for git-clone users only: `git clone --recurse-submodules https://github.com/bottech/skills.git`. For npx-skills users, the standalone clone command above is the only path.
